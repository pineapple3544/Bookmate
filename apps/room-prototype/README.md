# 픽셀 독서방 시제품

## API·DB 없이 실행

Node.js 24만 있으면 의존성 설치 없이 저장소 루트에서 실행합니다.

```bash
node apps/room-prototype/server.js
```

http://localhost:5173 에서 홈을 엽니다. 하단의 **방 만들기**로 책과 참여 인원(2~10명)을 정한 뒤 독서방에서 링크를 공유합니다. 방장은 시작 전 독서방에서 방 옵션을 수정할 수 있습니다. 전원이 참가하면 방장이 시작하고, 현재 독서자가 완독과 별점을 저장하면 다음 참가자에게 차례가 넘어갑니다. 모든 참가자가 완독한 책은 **내 서재**에 꽂힙니다. 책을 선택하면 감상평을 수정하거나 히스토리에서 참가자별 감상과 PNG 티켓을 확인할 수 있습니다.

방·참가자·감상평은 저장소 루트의 `.bookmate-exchanges.json`에 저장합니다. 예전에 `apps/room-prototype` 아래에 저장된 방도 읽습니다. `EXCHANGE_DATA_FILE`로 저장 경로를 지정할 수 있습니다. 초대 링크를 사용할 참가자는 모두 같은 서버 주소에 접속할 수 있어야 합니다. 독서방의 이동, 채팅, 페이지 사진 기록은 브라우저 로컬 모드이며 방별로 저장합니다.

픽셀 독서방만 체험하려면 http://localhost:5173/room.html 을 엽니다. 이 화면은 API 없이 실행됩니다. `file://` 대신 localhost 또는 HTTPS로 제공합니다.

Node 대신 Docker를 사용하려면 다음을 실행합니다. `.env`·PostgreSQL·API는 필요 없습니다.

```bash
docker compose -f compose.local.yaml up
```

기존 Compose가 5173을 사용 중이면 먼저 기존 web 서비스를 중지합니다.

## 현재 가능한 기능

- 바닥 클릭, 방향키·버튼 이동, 장애물 회피, 빈자리 착석·일어나기
- 사용자 1~4 선택, 독서 완료, 모바일 책·참가자·기록·채팅 접기
- 상단 **캐릭터 꾸미기**에서 머리 모양과 색, 상·하의, 신발색, 치장, 표정을 고릅니다. 피부색 원을 고른 뒤 그라데이션 바를 움직여 밝기를 조절합니다.
- 모든 참가자가 독서를 완료하면 책 표지 펫이 해금됩니다. 꾸미기에서 선택한 펫이 캐릭터를 따라다니며, 해금한 표지는 브라우저에 책 ID별로 저장됩니다. 시제품 독서방은 한 권으로 구성됩니다.
- **기록하기**에서 페이지별 사진을 올립니다. 현재 독서자와 이미 완독한 참가자가 기록을 열람할 수 있습니다. 게시물을 선택하면 댓글이나 사진을 추가하고, 원본 사진 위에 그림을 저장할 수 있습니다.
- 창밖은 브라우저의 현지 시간에 따라 아침(5시), 낮(8시), 노을(17시), 밤(20시)으로 바뀝니다.
- IndexedDB에 페이지 기록과 채팅 저장. 새로고침·탭 종료 후 재접속 시 복원
- 최대 500자 채팅, Enter 전송·Shift+Enter 줄바꿈, 한글 조합 입력 처리
- 채팅 기록 50건씩 조회, 이전 대화 불러오기, 재전송 ID 중복 방지
- 머리 위 말풍선 약 5초 유지 후 1초 페이드아웃. 과거 기록 조회 시 재생하지 않음
- 같은 브라우저 프로필·같은 Origin의 여러 탭에서 채팅·접속 상태·아바타 위치·완료 상태 공유
- 온라인 컬러·오프라인 흑백. 접속 신호 8초, 만료 25초, 채팅·접속 조회 1.5초
- 모션 감소 설정 지원. 방 상태 초기화는 위치·선택·완료 등 시제품 상태만 초기화하며 저장된 페이지 기록·채팅은 보존

여러 탭 시연은 각 탭에서 서로 다른 사용자 번호를 선택합니다. BroadcastChannel은 같은 브라우저 내 이동 공유용이며 인터넷 P2P가 아닙니다. 같은 아바타를 여러 탭에서 동시에 조작하는 권한 조정과 동시 좌석 예약은 제공하지 않습니다. 각 사용자는 페이지당 사진 게시물 하나를 올릴 수 있으며, 추가 코멘트는 게시물에 누적됩니다.

로컬 저장은 현재 브라우저·주소에 한정됩니다. 다른 기기·브라우저·포트에는 자동 복제되지 않으며 사이트 데이터 삭제, 브라우저 저장소 정리 시 사라질 수 있습니다. 저장소 차단·용량 초과 시 실패를 표시하고 채팅 입력을 보존합니다. 첫 로드 이후 네트워크 없이도 이동·기록·채팅 조작은 가능하지만, 정적 파일을 다시 로드하려면 해당 호스팅에 접근해야 합니다.

캐릭터 외형은 사용자 번호별로 브라우저에 저장되어 새로고침과 방 상태 초기화 후에도 유지됩니다. 같은 브라우저 프로필·같은 Origin의 탭에 반영되며, 서버 채팅 모드에서도 외형은 브라우저에 저장됩니다.

## 기존 서버 채팅 사용

```bash
# .env.example을 참고하여 .env 준비
docker compose up --build
```

http://localhost:5173/?mode=server 에 접속합니다. 기본 URL은 로컬 모드이며 서버 모드는 명시적으로 선택합니다. 연결 실패를 로컬 성공으로 바꾸지 않습니다. 로컬 채팅과 서버 채팅은 별도 저장소이고 자동 이전하지 않습니다.

서버 모드 채팅은 PostgreSQL에 보관되며 Room 삭제 시 CASCADE로 삭제됩니다. `PROTOTYPE_CHAT_ENABLED=true`에서만 시제품 API를 활성화합니다. 로그인 없는 사용자 번호 선택은 개발용입니다. Node로 웹만 실행할 때 `API_ORIGIN` 기본값은 http://127.0.0.1:3000 입니다.

API: GET/POST `/api/v1/prototype/chat`, POST `/api/v1/prototype/chat/presence`. GET의 before/after는 순번 커서이며 POST의 id는 재전송 중복 방지 UUID입니다.

## 검증

정적 웹을 실행한 상태에서 다음을 실행합니다.

```bash
npm ci
npx playwright install chromium
npm run test:browser -w @bookmate/room-prototype
```

`BASE_URL`로 주소를, `BROWSER_CHANNEL=chrome`으로 설치된 Chrome 사용을 지정할 수 있습니다. 테스트는 새 브라우저 컨텍스트에서 API 요청을 차단하고 로컬 채팅·동시 전송·페이지별 그림·탭 공유·반응형 화면을 검증합니다. 평소 사용하는 브라우저 데이터는 수정하지 않습니다.

## 후속 연동

방 참가에는 브라우저에 저장한 참가 토큰을 사용합니다. 계정 로그인, 방 삭제, 기기 간 사진·채팅·아바타 동기화, WebRTC는 후속 연동 항목입니다.
