# 옷장과 독서방 UI 구현 계획

**목표** 홈 기본 외형을 신규 참가 시점에 복사하고, 방에서는 픽셀 옷장을 통해 그 방의 외형을 편집한다. 독서방 주요 버튼, 온라인 상태, 모바일 이름표와 이동 조작을 함께 개선한다.

**구성** 기존 Canvas·DOM·Node·PostgreSQL을 유지하고 공용 편집기를 두 화면에서 사용한다. 사용자 기본 외형과 참가자 외형은 각각 독립된 값으로 보관한다.

## 1. 서버와 독립 실행 모드

1. 방 생성·최초 참가·재참가·기존 방에 대한 범위 검증을 추가한다.
2. Prisma User에 선택적 기본 외형을 추가한다. 인증된 GET/PATCH /api/v1/me/appearance의 응답은 { appearance }이며 PATCH 본문은 외형 객체다. 요청자 자신의 값만 갱신한다.
3. 생성과 첫 참가 시 현재 기본값을 저장한다. 기존 방의 외형, 외형 미지정 참가자, 재참가의 값을 유지한다. 독립 실행 모드는 브라우저 기본값을 생성·참가 때 전달한다.
4. PostgreSQL 통합 테스트와 타입 검사를 실행한다.

## 2. 두 옷장과 공용 편집기

1. 기존 외형·펫·미리보기·취소·저장 처리를 공용 모듈로 추출한다. 홈의 네 번째 탭과 방 가구가 같은 편집기를 연다.
2. 방의 왼쪽 의자를 픽셀 옷장으로 교체한다. 스테이지 좌표와 연결한 접근 가능한 조작 영역을 제공한다. 클릭·터치·키보드 동작과 카메라, 포커스 복귀를 검증한다.
3. 홈 탭, 두 방, 두 사용자에서 각각 저장·취소·재접속 후 외형을 확인한다.

## 3. 독서방 화면

1. 주요 버튼의 중심이 하단 메뉴와 겹치는지 확인한 뒤 화면 높이와 스크롤 여백을 조정한다.
2. 상대 참가자 행의 불투명도와 이름표 대비를 조정한다. 모바일에는 내 이름·현재 독서자·발화자·직접 선택한 아바타의 이름을 우선 표시한다.
3. 모바일 방향키를 접을 수 있게 하고 채팅 전송 영역을 44픽셀 이상으로 만든다. 키보드 접근과 좌석·채팅·이동 기능을 보존한다.
4. 375·390픽셀 모바일과 데스크톱 화면을 실제 브라우저에서 검사하고 기존 통합 테스트를 재실행한다.

## 리뷰 중점

이전 외형의 보존, 신규 참가 요청 재시도, 편집기의 저장 실패, 좁은 화면에서 가구 접근, 하단 메뉴에 가려진 버튼을 확인한다.
