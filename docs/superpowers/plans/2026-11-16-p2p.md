# P2P record sharing implementation plan

Goal: retain the authenticated Node/PostgreSQL server and exchange photo, reply, annotation and text-note bodies using WebRTC DataChannels.

Architecture: per-browser peers (not per-account sockets) form a small room mesh. The server authorizes and orders immutable operation metadata (actor, target, SHA-256 digest, size), never record bodies. IndexedDB stores verified operation bodies; recipients compare the server manifest before materializing records. Room readers/completed members only may exchange records. Ordered chunk transfer has bounded buffers, backpressure, retry and digest checks. All peers can seed verified historical bodies after the original author leaves. No server content fallback.

Choices: full mesh fits existing 2–10 members and avoids dependence on an elected host. Server metadata prevents forged authors and old deletes being undone; pure client-only trust was rejected. Existing login/chat/presence remain unchanged. No Sites. Existing records stay preserved; own local records import when eligible. Offline authors cannot commit new shared operations without server authorization. No promise of availability when every replica is offline or erased.
